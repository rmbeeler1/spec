# Acceptance: v0.3 "Plan" (DRAFT, awaiting owner confirmation)

The verb for this release: a writer plans and reshapes a script without leaving the app. Scenes become cards you can reorder, beats live on a freeform board, the outline shows acts and sequences at a glance, cut material goes to a stash instead of the trash, and a pacing view makes the shape of the whole script visible.

Each box names its planned proof:
- **(live)** = exercised in the running app by an automated driver, screenshot in `docs/evidence/`.
- **(tests)** = covered by the automated suite (`pnpm test`).
- **(manual)** = needs a human hand or eye; the owner checks it.

## Decisions to confirm before coding starts

These shape everything below. Silence on any of them means I go with the recommendation.

1. **Where planning data lives.** Recommendation: a sidecar file next to the script, `MyScript.spec.json` beside `MyScript.fountain`, instead of a required project folder. Opening a bare .fountain file keeps working exactly as today; the sidecar appears only once you use a planning feature. Card positions, colors, tags, tension values, and beat cards go in the sidecar keyed by stable element IDs. Script text never goes in it.
2. **Where stash text lives.** Stashed material is script text, and the rule is that script text lives only in Fountain. Recommendation: a `MyScript.stash.fountain` file next to the script, so cut material stays plain text and nothing is ever truly lost. The sidecar JSON holds only stash metadata (when cut, from where).
3. **Storylines.** The plan lists storyline lanes and storyline tags on cards. Recommendation: in v0.3, storylines are just tags with colors (defined in the sidecar, assignable to scenes); a dedicated storyline lane in the outline comes later if tagging proves useful. Keeps the outline view simple.

## Corkboard (index cards)

- [ ] (live) A Corkboard view shows one card per scene, auto-generated from scene headings, in script order, with the scene's synopsis (`=` line) as the card body.
- [ ] (live) Editing a card's synopsis writes it back into the script as the scene's `=` synopsis line (round-trips through Fountain).
- [ ] (live) Dragging a card to a new position reorders the actual scenes in the script, same result as the sidebar arrows.
- [ ] (tests) Reordering via cards preserves every element of every scene (no text loss, IDs stable).
- [ ] (live) Cards show scene color and tags; setting a color from the card updates the sidecar, never the Fountain text.
- [ ] (manual) Corkboard feels usable on the owner's real script: drag is smooth, text is readable at a glance.

## Pacing storyboard

- [ ] (live) A Pacing view lays the same scene cards left to right as a timeline, with act dividers taken from `#` sections.
- [ ] (tests) Each card shows estimated page length from the real pagination engine and running time at 1 page = 1 minute; numbers match `paginate` output on the corpus.
- [ ] (live) Each card shows INT/EXT and DAY/NIGHT parsed from its heading, plus its storyline tags.
- [ ] (live) Each card has a user-set tension value (for example 1 to 5), stored in the sidecar.
- [ ] (live) A strip view draws the tension curve across the whole script, so pacing problems are visible at a glance.
- [ ] (manual) The owner reads the curve on a real script and can point at a sag without opening a single scene.

## Beat Board

- [ ] (live) A freeform canvas of cards: title, body, color, tags. Create, edit, move, delete. Positions persist in the sidecar.
- [ ] (live) Cards can be linked with flow lines; lines survive save and reopen.
- [ ] (tests) Beat cards and their layout round-trip through the sidecar file (save, reopen, identical board).
- [ ] (live) Beat cards are planning-only: nothing on the board changes the Fountain file. Text-first per the decisions log; no image attachments in v0.3.

## Outline view

- [ ] (live) An Outline view shows lanes for Acts (`#`), Sequences (`##`), and Scenes, derived from the script's sections and headings.
- [ ] (live) Clicking an outline entry jumps the editor to that spot.
- [ ] (tests) Outline structure matches the parsed section depths on the corpus scripts that use sections.
- [ ] (live) Scenes without any sections still outline sensibly (one flat lane, no crash, no phantom acts).

## Stash

- [ ] (live) A stash pane holds cut material: select elements in the editor, send to stash, they leave the script and appear in the pane.
- [ ] (tests) Stashed text is stored as Fountain (per decision 2), never inside JSON; stash survives app restart.
- [ ] (live) Dragging (or a button) restores a stashed chunk back into the script at the cursor.
- [ ] (tests) Stash round-trip: stash then restore reproduces the exact original elements.

## Character navigator

- [ ] (live) A character list with dialogue counts and scenes-per-character, computed from the script.
- [ ] (tests) Counts are correct on corpus scripts with known character tallies (dual dialogue counted once per cue, (CONT'D) and (V.O.) variants merged to the base name).
- [ ] (live) Selecting a character filters or highlights the script to their scenes or cues.

## Scene coloring and tagging

- [ ] (live) Scenes can be given a color and tags from the sidebar, corkboard, or pacing view; shown consistently in all of them.
- [ ] (tests) Colors and tags live in the sidecar keyed by element ID and survive scene reordering and script edits around them.

## Cross-cutting

- [ ] (tests) The sidecar is written atomically like the script (temp file then rename) and a missing or corrupt sidecar never blocks opening the script; worst case the planning data is reported as unreadable and the script opens clean.
- [ ] (tests) Stable element IDs: reordering, editing, and stashing do not reassign IDs of untouched elements, so planning data never silently detaches.
- [ ] (live) All new views are reachable from a View menu and from a visible control in the app (no hidden-feature repeat of the title page lesson).
- [ ] (manual) Editor performance on a 120-page script is still fine with planning views open (keystroke latency feels unchanged).
