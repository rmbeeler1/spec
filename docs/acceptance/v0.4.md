# Acceptance: v0.4 "Produce" (DRAFT, awaiting owner confirmation)

The verb for this release: a script goes through production hands without leaving Spec. Revisions are tracked the way the industry expects (colored sets, asterisks, omitted scenes), scenes carry numbers, two people can talk at once, and the script answers questions about itself (reports, stats).

Each box names its planned proof:
- **(live)** = exercised in the running app by an automated driver, screenshot in `docs/evidence/`.
- **(tests)** = covered by the automated suite (`pnpm test`).
- **(manual)** = needs a human hand or eye; the owner checks it.

Release gate (per CLAUDE.md): build, verify, write the report, then stop; the owner checks the manual boxes before v0.4.0 is tagged.

## Decisions to confirm before coding starts

1. **Where revision data lives.** Fountain has no revision syntax, and the rule is that script text lives only in the Fountain file. Recommendation: revision SETS (name, color, date) and per-element revision MARKS live in the sidecar keyed by element IDs; OMITTED scenes stay in the script itself as a scene heading whose text is "OMITTED" (the industry look, visible in any editor). The Fountain file stays clean and portable; lose the sidecar and you lose marks, never text.
2. **Page locking and A-pages scope.** This is the big rock of v0.4: locked pages mean new material grows pages 12A, 12B instead of renumbering, which cuts deep into the pagination engine. Recommendation: ship v0.4 in two steps inside the release: revision sets, marks, asterisks in the margin, omitted scenes, and scene numbering first; then page locking + A-pages against the Final Draft parity corpus before calling the release done. If locking turns out to need more than the release can carry, it moves to v0.4.1 with your sign-off, not silently.
3. **Reports format.** Recommendation: a Reports view in-app (scene list, characters, locations, INT/EXT, DAY/NIGHT, dialogue counts) with one-click export of any report as plain text and CSV. No PDF report layouts in v0.4.
4. **Writing stats home.** Session stats (words and pages per day, streaks, goals) are personal, per-script data. Recommendation: they live in the sidecar; a goal is set per script. No cloud, no telemetry, ever.
5. **New templates.** Stage play, audio drama and comic are different FORMATS, not just different first pages. Recommendation: v0.4 ships them as starter templates plus adjusted element layouts (indents, widths, cue style) in the editor and PDF, but Final Draft parity remains a screenplay-only promise. Say so in the README.

## Revision mode

- [ ] (live) A revision set can be started (name, standard color order: White, Blue, Pink, Yellow, Green...), shown in the UI, and closed; sets are listed with dates.
- [ ] (tests) Elements edited while a set is active get that set's revision mark, stored in the sidecar by element ID; marks survive save, reload, and rename.
- [ ] (live) Revised elements show an asterisk in the editor margin, tinted by the active set's color.
- [ ] (live) PDF export prints revision asterisks in the right margin on marked lines.
- [ ] (live) A scene can be marked OMITTED: its content moves to the stash (nothing deleted), the heading stays as "OMITTED" with its scene number, and the corkboard/pacing cards show it as omitted.
- [ ] (tests) Un-omitting restores the scene exactly from the stash.
- [ ] (live) Page locking (per decision 2): with pages locked, inserting material creates A-pages (12A) instead of renumbering, and the page map shows them; removing material leaves short pages rather than pulling text up across a lock.
- [ ] (tests) A-page numbering matches Final Draft conventions on the parity corpus scripts with simulated insertions.
- [ ] (manual) The owner runs one real revision pass (start Blue, edit five scenes, export PDF) and the output reads like a production draft.

## Scene numbering

- [ ] (live) One command numbers all scenes (1, 2, 3...), stored as Fountain `#1#` markers in the file itself; numbers show in the editor, sidebar, corkboard, outline, and PDF (both margins, industry style).
- [ ] (tests) Numbering round-trips through Fountain and FDX.
- [ ] (live) With numbering locked, new scenes get A-numbers (12A) and omitted scenes keep their number on the OMITTED heading.
- [ ] (tests) Renumbering (unlock and renumber) is one undoable operation.

## Dual dialogue

- [ ] (live) Two consecutive speeches can be marked dual (the second cue takes Fountain's `^`); the editor renders them side by side.
- [ ] (tests) Dual dialogue paginates side by side without breaking either column across a page, and round-trips through Fountain and FDX (the model's `dual` flag already carries it).
- [ ] (live) PDF export prints dual dialogue in two columns at standard margins.

## Reports

- [ ] (live) A Reports view with: scene list (number, heading, page, length), characters (cues, scenes, first appearance), locations (scene counts), INT/EXT and DAY/NIGHT breakdowns, dialogue counts per character.
- [ ] (tests) Report numbers are computed from the same core stats the planning views use, verified on corpus scripts with known tallies.
- [ ] (live) Any report exports as plain text and CSV.

## Writing stats and goals

- [ ] (live) A stats panel shows words and pages written today and per session, with history since the script began.
- [ ] (tests) Stats accumulate correctly across sessions in the sidecar and never count imported text as "written today."
- [ ] (live) A per-script goal (pages or words per day) shows progress in the status bar.

## Templates

- [ ] (live) New from Template gains Stage Play, Audio Drama, and Comic, each a sensible starter document.
- [ ] (live) Their element layouts (indents, widths, cue style) apply in the editor and PDF per decision 5.
- [ ] (manual) The owner eyeballs one page of each against a reference sample.
