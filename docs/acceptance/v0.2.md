# Acceptance: v0.2 "Import" (confirmed by the owner, Oct 12, 2026)

The verb for this release: a writer with a script trapped in Word, Final Draft, plain text, Markdown, or a PDF gets it into Spec as correctly typed screenplay elements, fixes any misreads in bulk, and keeps writing.

Each checked box names its proof and HOW it was verified:
- **(live)** = exercised in the running app by an automated driver, with a screenshot in `docs/evidence/`.
- **(tests)** = covered by the automated suite (`pnpm test`) but not yet exercised in the running app.

## Element classifier (packages/core)

- [x] (tests) Classifies plain text lines into screenplay elements using INT./EXT. patterns, ALL CAPS cues, transitions ending TO:, parentheticals, and blank-line context. `classifier unit cases` suite.
- [x] (tests) Uses layout hints when the source has them (centered, indented, bold) to raise confidence. `uses layout hints when present`.
- [x] (live) Every classified line carries a confidence value so the review pane can sort doubtful lines first. Seen in the app: `v0.2-md-review-pane.png` (doubtful-first on by default, lone 60% line sorted to the top).
- [x] (tests) Accuracy gates on the corpus: at least 95% of lines correctly typed on clean sources, at least 85% on messy ones. `accuracy gates on the corpus` suite. The real-world messy fixture `test-corpus/md/EL_AHOGADO_Screenplay.md` has its own gate: all 60 scene headings found, 64 sections, 700+ cues, under 10% doubtful (`markdown.test.ts`).

## Importers (packages/core)

- [x] (tests) .txt import through the classifier. `importPlainText end to end`.
- [x] (live) .md import: inline bold/italic markers and --- rules stripped before classification, bold kept as a confidence hint, # headings mapped to Fountain sections with depth, front matter (title, Written by, Based on) routed to the title page. Verified live with EL_AHOGADO: 60 scenes in the sidebar, 84 pages (`v0.2-md-review-pane.png`, `v0.2-md-imported.png`); previously imported as one 87-page block with 0 scenes.
- [x] (live) .docx import: paragraphs, alignment, indent and bold hints from the document XML, then classified. Verified live by dropping Brick And Steel.docx (`v0.2-review-pane.png`, `v0.2-imported-result.png`).
- [x] (tests) .fdx import wired into the app's import flow (loads directly, element types are explicit). `routeImport > loads fountain and fdx directly`.
- [x] (live) .pdf text-layer import, best effort, same classifier; scanned PDFs produce a clear error. Verified live by dropping Brick And Steel.pdf after the worker fix (`v0.2-pdf-import.png`, re-confirmed on the current build); error path covered by tests (`rejects a PDF without a text layer`), plus a browser-code-path regression test (`pdf.browser.test.ts`) that reproduces the renderer's workerSrc failure when the fix is absent.
- [x] (tests) Round-trip per source format: import, serialize to Fountain, reparse, element counts stable (txt, md, docx, pdf; fdx from v0.1).

## App flow

- [x] (live) Drag-and-drop onto the window imports .fountain, .fdx, .docx, .pdf, .txt, .md; File > Import… (CmdOrCtrl+Shift+I) uses the same handler. The drop path is driver-verified; the native menu item has not been driver-clicked (native menus are outside the driver's reach) — owner sanity check: File > Import… once.
- [x] (live) Imports open in a review pane with per-line type and confidence, a summary line with a sanity check ("Found 0 scene headings … that's unusual" style), a what-to-do explainer, doubtful-first on by default, click/shift-click selection, bulk type-set, and a one-click "Looks right — import" path. `v0.2-md-review-pane.png`.
- [x] (live) Committing the review produces an untitled document in the editor; nothing is written to disk until the writer saves. Status bar after commit: "84 pages · 60 scenes · Untitled — Not saved to a file yet".
- [x] (tests) CLI gains the same importers: `spec convert input.docx output.fountain`, same for .txt/.md/.pdf. `convertFile` suite.
